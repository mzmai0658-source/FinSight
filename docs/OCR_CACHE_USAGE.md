当前新语料采用10家新公司的120份原件，118份已有本轮远端PaddleOCR-VL-1.6新OCR；DeepSeek负责生成，百炼`text-embedding-v4`生成1024维向量。实际进度与未核验边界见[本轮OCR试验](UPGRADE120_OCR_TRIAL.md)。原PDF、OCR JSON/MD、远端作业号及身份元数据分别留存，新OCR完成不等于所有数字核实完成。

本轮默认已选择新118份云端试验库，保持`experimental / relaxed_ocr`和待核验提示。旧117份/BGE及其缓存单独保留，不与新默认混用。

本轮首次识别后可复用已完成作业和相同摘要的结果；中断时续查原作业，提交结果不确定时先对账，不自动重复付费提交。复用仍需检查PDF/OCR摘要、模型身份、物理页及来源；云端向量与旧BGE空间隔离。以下资料包与数字只描述**历史117份/BGE兼容路线**，不计入本轮新语料成绩。

## 历史缓存的用途与选择

缓存是以前对真实 PDF 的识别结果，包含文字、表格和页面布局，不是虚构财报或问答标准答案。首次安装可选择复用，已有环境继续保留当前匹配版本。

| 方式 | 需要的资料 | 既有验证与边界 |
| --- | --- | --- |
| 已核验事实快速初始化 | 真实 PDF 和运行配套资产 | 此前在空隔离库、空索引中完成快速安装，未导入 OCR 文件 |
| 重新提取并复用 OCR | 同版本真实 PDF、OCR 包及定位审核资料 | 此前对 117 份完整重建，表格和检索正文来自 OCR，PDF 用于核对 |
| 重新提取且不复用 OCR | 真实 PDF 和自行配置的兼容 OCR 服务 | 此前仅一份 10 页真实季报完成识别和部分抽取；28/46 条值一致、18 条缺失，未达到缓存同等完整度 |

缓存只省去识别步骤，不能省去数值、单位、口径、年份、页码和来源检查。OCR 存在不代表识别全文正确，也不表示成员人工审核了全文。无缓存但需重新抽取时，必须配置兼容 OCR 服务；现有抽取程序不会自动补足同一套表格结果。

## 文件与身份

ZIP 按项目相对目录保存 OCR JSON 和 `.meta.json`。三个资料包各带 `PACKAGE_MANIFEST.json`，并由共同的 `PACKAGE_SET.json` 绑定。清单和报告目录记录公司、报告期、PDF/OCR 指纹、页数和模型标识；初始化程序完整校验后将缓存放到对应 PDF 旁边，不混用历史独立 OCR 附件清单。

旧缓存缺少生成时的身份元数据时，导出包补充的是基于已验收清单的当前绑定记录，不表示恢复了历史生成时间或 OCR 服务授权。原始 JSON 字节不修改，也不改写源缓存和旧验收记录。
