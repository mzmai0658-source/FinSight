# 真实财报200轮：修复机制与证据

这轮问答、标准答案、截图和技术报告只使用117份真实报告。旧合成演示的20题成绩不进入本轮。全部运行经Java/SSE、Python Agent、真实Ollama与只读MySQL；对话使用真实保存状态。

## 首轮问题和共同原因

原始200轮及初评分保存在本机`data/runtime/qa200/run0`，不覆盖。评分工具修正另存`rescored_records.jsonl`和`scoring_corrections.json`；独立叙述复核另存`reviewed_records.jsonl`。成员人工审核没有开展，不把助手核对写成团队人工审核。

| 共同问题 | 改造方式 | 防止再次发生的约束 |
|---|---|---|
| 模型混淆明确指标、口径或单位 | 在唯一结构提案入口登记原话中的无歧义条件；保留模型的集合操作 | 不按关键词跳过理解；冲突、非唯一含义继续询问或阻断 |
| 同比被要求同时查询金额与披露增长率 | 区分基础指标和已披露增长率这两种实现 | 明确问原文披露增长率仍按原要求查询 |
| 柱状图比较被要求额外添加重复compare目标 | 图表可兑现可视比较；明确要谁高、差额或结论时仍要求相应目标 | 不能用有一张图替代明确计算 |
| 只留一家被错误公共/局部公司修改覆盖 | 编译全局keep，移除同目标内冲突的局部公司修改 | 不丢弃不同内容的无效目标编辑；结构错误仍失败 |
| 原文单位不要改写被当成不查数字 | 将引用限制与查询否定分开 | 仅针对明确新查询和单位否定；真正不查数照常保留 |
| 用户排除年份被当成必须查询 | 正向年份与直接否定年份分开 | 日期范围仍展开，中间年份不能丢失 |
| 比较基期被误当成另一个同比目标 | 根据明确相对关系登记目标期间，基期仅作为计算输入 | 分别查询每年同比仍逐年计算，不偷减任务 |
| 概念定义过短和回答顺序不符 | 完整目录定义，按目标顺序先解释再交付数字 | 财务正文继续由程序生成，不让模型编数字 |
| 利润原因被拿来解释营业收入 | 仅保留原文中以目标指标为主语的因果段落，逐字引用并保留位置 | 检索不足时保留可靠金额，原因标记未确认 |
| 缺原因但标记已完成 | 缺证据解释不作为正向原因声明通过 | 实际目标状态为no_data/partial，不能伪装整轮完成 |

## 评分工具的修正边界

修正比较结论未要求重复输入金额、lookup/compare两种等价计算目标、未指定单位的独立换算、毛利率等价数学定义。增加实际比较关系、计算公式和显示单位检查，并单列发布了请求外事实的严重错误。未改变题目、原件值、年份、单位要求、口径或允许的任务边界。

每次修复后使用同一200题完整复跑；正式成绩不拼接成功题。使用过的题属于回归，不能称全新盲测。严重错误即使总分达到85%也不能通过。最终成绩和剩余失败见`docs/evidence/real200/RESULTS_200.md`。
